# Explore notes: r-publish-gate-and-launch

Working note. Evidence that the publish skill, both scripts and the source tree were read, and experiments run in the scratchpad (never in the target tree). `policy.json` was inspected for its structure only; no content of it is copied here.

## 1. Skill procedure (`commercetools-labs-publish/SKILL.md`, 0.29.4)

Step 1 prepare in a fresh clone -> `ossify.mjs --repo . --apply --year <year>`; write `SUPPORT.md`, `CONTRIBUTING.md`, README opening paragraph ("unsupported" x3: file header, README banner, SUPPORT.md). Step 2 strip history: `rm -rf .git && git init -b main`, `git add --dry-run .` and READ it, one commit. Step 3 gate: `node gate.mjs --repo .` immediately before the push that makes the repo public. Step 4 publish public from the start (never private-then-flip: a force-push does not remove old commits), `gh repo create commercetools/<name> --public --description`, `git push -u origin main`, set org custom property `commercetools-labs=true` via `gh api -X PATCH repos/commercetools/<name>/properties/values`, topic `labs`; 422 means the org property is not defined yet; then anonymous clone proof (`npm ci && npm run typecheck && npm test && npm run build`). This repo uses Yarn, so the proof is adapted (design D-8).

## 2. `ossify.mjs` behaviours (read from `scripts/ossify.mjs`, 293 lines)

* Dry run by default; `--apply` writes; `--year` defaults to the current year (pass `2026` to match the locked header). Exit code is always 0: **its report is advisory**.
* Writes root `LICENSE` (MIT, holder "commercetools GmbH and the commercetools-labs contributors") only with `--apply`.
* Header styles by extension: `.ts .tsx .js .jsx .mjs .cjs .mts .cts .css .scss .java .kt .kts` block comment; `.swift` `//`; `.graphql .sh` `#`. Skips (never headered): `.json .lock .md .svg .png ... .yaml .yml .toml .txt .snap` and others; skips dirs `.git node_modules public dist build coverage .next .turbo ...`; skips generated paths (`types/generated/`, `generated/`, `*.generated.*`, `graphql.ts`, `*-lock.*`). Files with other extensions (e.g. `.html`, `.example`, `.cjs` is fine) are listed under "no comment style".
* A file whose first 800 chars contain `SPDX-License-Identifier:` is left alone ("already").
* **Foreign copyright refusal**: if the first 2000 chars match `(Copyright|(c)) ... ` and the matched text does not contain "commercetools" (case-insensitive), the file is NOT headered and is reported. The regex is case-insensitive and loose: it matches the identifier `copyright` in code. Experiment (scratchpad `fx/`): a file containing `interface P { copyright: string; }` in its first lines was refused ("FOREIGN COPYRIGHT ... copyright: string;"), left without a header, and the gate then reported both "missing SPDX header" and "foreign copyright" for it. The source has such files: `puck/packages/puck-components/src/components/cms/FooterBlock.tsx` (prop `copyright`, lines 9, 12, 35), `puck/packages/puck-editor/src/components/cms/FooterBlock.tsx`, `service/src/samples/CMS/footer-block.ts` (lines 28-80). Remedy decided in design D-4: put the exact SPDX header into those files by hand IN THE DEV TREE (then ossify reports "already" and the gate sees our header first), or rename the prop.
* **Third-party directory rule**: any non-root directory containing `LICENSE`, `LICENCE` or `COPYING` (any suffix) - or a `metadata.json` naming a non-commercetools organization - is skipped as a whole subtree and printed under "THIRD-PARTY DIRECTORIES EXCLUDED". Experiment on a copy of the source: `service  (has its own LICENSE file)` -> the whole `service/` tree (~12k LOC) is excluded from headering. Source `service/LICENSE` is a generic MIT template with placeholders (`Copyright <YEAR> <COPYRIGHT HOLDER>`). It must NOT exist in the target (spec A must not copy it; R re-verifies and deletes it from the release tree if present).
* `package.json` renaming: every `package.json` outside skipped dirs whose `name` is not `@commercetools-labs/...` is rewritten to `@commercetools-labs/<unscoped name>`; `homepage`, `repository`, `bugs` GitHub URLs are repointed to org `commercetools`. Experiment on the source: 14 package.json files would be renamed (root workspace + 10 packages + playground + MC wrapper + mcp). In the target all names are already scoped by spec A/I/L/M, so a correct tree gives "0 renamed"; a non-zero count means an earlier spec missed one (fix in the dev tree).
* Reported counts on a copy of the source (scratchpad `rel/`, cms folders excluded): 234 would be headered, 63 data/docs, 15 "no comment style".

## 3. `gate.mjs` behaviours (read from `scripts/gate.mjs`, 326 lines)

* Usage: `--repo <path>` (required), `--ref <sha>` (default HEAD), `--ack`, `--no-history`, `--policy <file>` (default `policy.json` next to the script). Exit 0 clear (or warnings acknowledged), 1 findings, 2 usage error **or dirty tree**. Experiment: with an untracked file present it printed "REFUSING TO RUN: working tree is not clean ... Commit or stash first." and exited 2.
* It scans the commit it names (`--ref`) plus every ancestor commit (changed files per ancestor) unless `--no-history`; it prints the commit sha, subject, history count and file count first so the operator can see WHAT was scanned.
* Checks, in order: (1) forbidden tracked files by path regex (`.env`, `.env.local`, `*.pem`, `*.p12`, `*.key`, `service-account*.json`, `.npmrc`) -> FAIL; (2) SPDX header within the first 600 chars for tracked files with extensions `.ts .tsx .js .jsx .mjs .cjs .swift .kt .java`, except generated paths (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `schemas/`, `types/generated/`, `public/`, `dist/`, `build/`, `.next/`) -> FAIL; (2b) **third-party subtree**: any tracked LICENSE/LICENCE/COPYING (any suffix) that is not at the repo root -> FAIL for that directory; foreign copyright in the first 2000 chars of the same source files -> FAIL; (3) required root files `LICENSE`, `SUPPORT.md`, `CONTRIBUTING.md` -> FAIL; package names: every tracked `package.json` (not under node_modules) that has a `name` not starting with `@commercetools-labs/` -> FAIL; (4) content scan of the tracked tree: secrets (everywhere, including lockfiles), customer/prospect names with word boundaries, internal-infrastructure identifiers -> FAIL; review-names and demo/POC/pre-sales framing -> WARN (these two groups skip generated paths); (5) same content scan on ancestors.
* Severity logic: any FAIL -> "BLOCKED", exit 1, and `--ack` does NOT help. WARN only -> "BLOCKED on warnings" exit 1 unless `--ack`, then "CLEAR (warnings acknowledged)" exit 0. `--ack` is a single switch for all warnings: there is no per-finding acknowledgement, so each WARN must be reviewed before using it.
* Findings print grouped by check with path:line, the match and 150 chars of context, max 15 per group ("... and N more"): to see all, fix the first 15 and re-run, or run with a larger terminal buffer and redirect to a file.
* Because the gate refuses a dirty tree and scans the commit, any fix after a run needs a new commit; the skill says squash rather than add a fixup; the owner's flow narrows that: squash only for leaks, otherwise normal commits while the gate stays clean (design D-10). The release procedure therefore re-creates the unpublished initial commit before the first push, and uses normal follow-up commits (gate on HEAD plus all ancestors) after it.

## 7. Risks

1. First 15 findings per check only are printed: loop until clear.
2. Burning an npm version: published versions cannot be republished; an unpublish is only possible within a short window and breaks consumers. Hence the gate must be green on a scratch commit of the final tree BEFORE the first `npm publish` (design D-5).
3. The admin-app lockfile needs the puck packages on the registry (Connect cannot resolve workspace packages): the lock can only be generated after the publish, hence the ordering (owner flow, no private fork): scratch gate -> npm publish of the rc (public packages) -> pin + lock -> squashed initial commit -> gate -> public repo + push -> tag rc -> Connect tests from the same repository by tag -> fixes as normal commits (gate clean) -> final 1.0.0.
4. Commit author identity is public: confirm which name/email before committing (checkpoint).
5. `openspec/changes/**` and `plans/**` contain internal paths and the words the gate warns about; they are not published (design D-3).
